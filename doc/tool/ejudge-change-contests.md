# ejudge-change-contests

Навигация: [Система ejudge](../система_ejudge.md)/[Использование](../использование.md)/[Общая архитектура системы](../общая_архитектура_системы.md)/[ejudge-change-contests](ejudge-change-contests.md)

Программа доступна с версии [3.9.0](../change/изменения_в_версии_3.9.0.md).

Утилита пакетного редактирования настроек турниров ejudge.
Предназначена для массового изменения атрибутов турниров в их конфигурационных
файлах [`contest.xml`](../contest.xml.md) и глобальной БД пользователей и
файла полномочий `capabilities.xml` — без ручного редактирования XML.

Использование:

```bash
ejudge-change-contests [OPTIONS] [CONTEST-IDS]...
```

Параметр CONTEST-IDS задает либо один номер турнира, либо диапазон
номеров турниров, например, `102-110`. В командной строке могут
указываться несколько номеров турниров или диапазонов.
Обрабатываются
только **уже существующие** на диске турниры, попадающие в указанный диапазон;
несуществующие номера пропускаются.

Примеры:

```bash
ejudge-change-contests --open 5
ejudge-change-contests --close 1-10
ejudge-change-contests --add-judge-cap someuser 7 8 9
ejudge-change-contests --add-master-cap admin --db --global --name "Admin Adminov" 1-20
```

Опции задают действия, которые необходимо выполнить над указанными
турнирами.

## Назначение

Для одного или нескольких турниров (в том числе целыми диапазонами) утилита
позволяет:

- открывать / закрывать турнир (флаг `closed`);
- делать турнир видимым / невидимым (флаг `invisible`);
- разрешать / запрещать доступ к CGI-интерфейсам `users`, `register` и `client`
  (он же `team`) для всех IP-адресов;
- изменять полномочия (capabilities) пользователя: добавлять предопределённые
  наборы `JUDGE`, `MASTER`, `FULL` или полностью снимать полномочия
  (на уровне турнира — в `contest.xml`, на глобальном уровне — в
  `capabilities.xml`);
- синхронизировать изменения с базой данных пользователей: регистрировать
  привилегированных пользователей в турнирах, снимать регистрацию либо
  «блокировать» пользователя в турнире;
- обновлять имя пользователя (`--name`);
- добавлять в `contest.xml` аудит-комментарий о произведённых изменениях
  (можно отключить);
- при изменении файлов создавать их резервные копии.

Утилита **идемпотентна**: если для турнира изменение не требуется (целевое
состояние уже достигнуто), файл не перезаписывается.

## Опции командной строки

Поддерживаются следующие опции:

### Атрибуты турнира

| Параметр | Назначение |
|----------|------------|
| `--open` | снять флаг `closed` (открыть турнир) |
| `--close` | установить флаг `closed` (закрыть турнир) |
| `--visible` | снять флаг `invisible` (сделать турнир видимым) |
| `--invisible` | установить флаг `invisible` (скрыть турнир) |
| `--no-users` | запретить доступ к CGI `users` со всех IP |
| `--all-users` | разрешить доступ к CGI `users` со всех IP |
| `--no-register` | запретить доступ к CGI `register` со всех IP |
| `--all-register` | разрешить доступ к CGI `register` со всех IP |
| `--no-participant` | запретить доступ к CGI `client`/`team` со всех IP |
| `--all-participant` | разрешить доступ к CGI `client`/`team` со всех IP |

### Полномочия пользователя (уровень турнира)

| Параметр | Назначение |
|----------|------------|
| `--remove-cap USER` | снять все полномочия у пользователя `USER` |
| `--add-judge-cap USER` | установить пользователю `USER` предопределённый набор `JUDGE` |
| `--add-master-cap USER` | установить пользователю `USER` предопределённый набор `MASTER` |
| `--add-full-cap USER` | установить пользователю `USER` предопределённый набор `FULL` |
| `--login USER` | указать пользователя, если операция изменения полномочий не запрошена (используется с `--db`) |

### Работа с БД пользователей и глобальным уровнем

| Параметр | Назначение |
|----------|------------|
| `--db` | дополнительно выполнить регистрацию/снятие регистрации в базе данных пользователей |
| `--lock` | при `--remove-cap` + `--db` — заблокировать пользователя в турнире вместо снятия регистрации |
| `--global` | дополнительно выполнить операцию на глобальном уровне (в `capabilities.xml`) |
| `--oauth` | обновить oauth-алиасы пользователя в `capabilities.xml` (совместно с `--global`) |
| `--name NAME` | обновить имя пользователя в турнирах или глобальное имя пользователя |

### Прочее

| Параметр | Назначение |
|----------|------------|
| `--no-audit` | не добавлять аудит-комментарий в `contest.xml` |
| `--ejudge-xml-path FILE` | задать путь к `ejudge.xml` (вместо встроенного `EJUDGE_XML_PATH`) |
| `--ejudge-contests-dir DIR` | задать каталог турниров напрямую (минуя `ejudge.xml`) |
| `--help` | вывести краткую справку и завершиться |
| `--version` | вывести версию и дату сборки и завершиться |
| `--` | прекратить разбор параметров; всё после считается идентификаторами турниров |

### Конфликты параметров

Следующие пары параметров **взаимоисключающие** (одновременное указание
приводит к ошибке и завершению с кодом `1`):

- `--open` и `--close`;
- `--visible` и `--invisible`;
- `--no-users` и `--all-users`;
- `--no-register` и `--all-register`;
- `--no-participant` и `--all-participant`.

Также за один запуск можно указать **ровно один** из параметров, задающих
пользователя: `--remove-cap`, `--add-judge-cap`, `--add-master-cap`,
`--add-full-cap` или `--login` (повторное задание пользователя — ошибка).

## Источники данных

### Каталог турниров

Если не задан `--ejudge-contests-dir`, утилита:

1. использует путь к `ejudge.xml`, заданный `--ejudge-xml-path` либо
   встроенный на этапе сборки путь `EJUDGE_XML_PATH`;
2. читает из `ejudge.xml` каталог турниров (`contests_dir`);
3. получает список турниров из этого каталога.

Если путь к `ejudge.xml` не задан ни одним из способов, либо `contests_dir` не
указан — утилита завершается с ошибкой.

### Сервер пользователей (ej-users)

Если указан `--db` (или `--global`), утилита подключается к серверу
пользователей по UNIX-сокету `socket_path` из `ejudge.xml` и проходит админ-
аутентификацию. По логину (`--login` либо пользователь из
операции изменения полномочий) она определяет `user_id`.

### Файл полномочий (`capabilities.xml`)

При `--global` утилита работает с глобальным файлом полномочий
(`caps_file` из `ejudge.xml`).

## Полномочия (capabilities)

### Уровень турнира (`contest.xml`)

Утилита работает с записями полномочий пользователей в турнире:

- `--remove-cap USER` — удаляет все записи полномочий для `USER`;
- `--add-judge-cap USER` / `--add-master-cap USER` / `--add-full-cap USER` —
  создаёт или обновляет (`upsert`) запись полномочий, устанавливая предопределённый
  набор `OPCAP_PREDEF_JUDGE` / `OPCAP_PREDEF_MASTER` / `OPCAP_PREDEF_FULL`.

Если нужная запись уже есть — изменение не выполняется (идемпотентность);
если запись есть, но набор другой — она заменяется.

### Глобальный уровень (`capabilities.xml`, только с `--global`)

Применяются отдельные предопределённые наборы глобальных полномочий:

| Набор | Состав |
|-------|--------|
| `JUDGE` | `JUDGE_LOGIN` |
| `MASTER` | `JUDGE_LOGIN`, `MASTER_LOGIN`, `LIST_USERS`, `GET_USER` |
| `FULL` | всё из `MASTER` + `CREATE_REG`, `EDIT_REG`, `DELETE_REG`, `PRIV_*REG`, `CREATE_USER`, `EDIT_USER`, `DELETE_USER`, `DUMP_USERS`, `EDIT_PASSWD`, `PRIV_EDIT_PASSWD`, `EDIT_CONTEST`, `CONTROL_CONTEST`, `RESTART`, `UNLOAD_CONTEST` |

- `--add-*-cap` — `upsert` глобальных полномочий;
- `--remove-cap` — удаление глобальных полномочий;
- `--oauth` (в сочетании с `--global` и операцией полномочий) — добавляет или
  удаляет oauth-алиас пользователя в `capabilities.xml`.

## Операции с базой данных пользователей (`--db`)

После правки `contest.xml` (и глобального файла) утилита синхронизирует БД
пользователей для каждого обработанного турнира:

- **`--remove-cap`**: пользователь либо **снимается с регистрации** в турнире,
  либо, если задан `--lock` и пользователь имеет статус `REG_OK`, **блокируется**
  в турнире (устанавливается флаг `LOCKED`). Если регистрации в турнире нет —
  операция считается успешной без изменений.
- **`--add-judge-cap` / `--add-master-cap` / `--add-full-cap`**: пользователь
  **регистрируется** в турнире как привилегированный (флаги
  `INVISIBLE | PRIVILEGED`, статус `REG_OK`). Если задан `--name` — сначала
  обновляется имя пользователя (поле `USERLIST_NC_NAME`).

Перед этим, если заданы `--db` и `--login` (или пользователь из операции
полномочий), выполняется поиск `user_id` по логину.

## Резервные копии и атомарная запись

Файл `capabilities.xml` обновляется **атомарно** и **безопасно**:

- новое содержимое сначала записывается во временный файл
  (`<имя>.new.<случайный>`), создаваемый с флагами `O_EXCL | O_NOFOLLOW` и
  правами `0600`;
- если содержимое не изменилось — выводится сообщение «file ... is unchanged» и
  файл не переписывается;
- иначе текущий файл сохраняется как резервная копия
  `<имя>.bak.<ГГГГММДДЧЧММСС.мс>`, а на его место атомарно ставится новый файл; при этом сохраняются режим доступа и
  gid исходного файла;
- хранится **не более 10** последних резервных копий файла `capabilities.xml`, более старые удаляются.

## Аудит-комментарий

Если не задан `--no-audit` в конце XML-файла турнира добавляется комментарий:

```xml
<!-- audit: ejudge-change-contests: <КОДЫ-ОБНОВЛЕНИЙ>, <ДАТА> -->
```

где `<ДАТА>` — текущее время в формате XML, а `<КОДЫ-ОБНОВЛЕНИЙ>` — коды
произведённых изменений.

### Коды обновлений

| Код | Значение |
|-----|----------|
| `+O` | турнир открыт (снят флаг `closed`) |
| `-O` | турнир закрыт (установлен флаг `closed`) |
| `+V` | турнир сделан видимым (снят флаг `invisible`) |
| `-V` | турнир сделан невидимым (установлен флаг `invisible`) |
| `+U` | разрешён доступ к `users` со всех IP |
| `-U` | запрещён доступ к `users` со всех IP |
| `+R` | разрешён доступ к `register` со всех IP |
| `-R` | запрещён доступ к `register` со всех IP |
| `+P` | разрешён доступ к `client`/`team` со всех IP |
| `-P` | запрещён доступ к `client`/`team` со всех IP |
| `+AJ` | добавлен/обновлён набор `JUDGE` |
| `+AM` | добавлен/обновлён набор `MASTER` |
| `+AF` | добавлен/обновлён набор `FULL` |
| `-A` | удалены все права пользователя |

## Выводимые сообщения

Для каждого изменённого турнира на стандартный вывод печатается строка:

```
<N>: <КОДЫ-ОБНОВЛЕНИЙ>
```

Например: `5: +O+U`. При ошибках выводятся сообщения вида
`N: failed to load contest` и `N: failed to save contest`, а счётчик ошибок
увеличивается.

## Коды завершения

| Код | Условие |
|-----|---------|
| `0` | успешное завершение (в том числе, если идентификаторы турниров не указаны) |
| `1` | ошибка разбора параметров/турниров; либо хотя бы один турнир не удалось загрузить или сохранить; либо ошибка операции с БД пользователей; либо ошибка сохранения `capabilities.xml` |

## Примеры

Открыть турнир 5:

```bash
ejudge-change-contests --open 5
```

Закрыть турниры с 1 по 10 и запретить регистрацию:

```bash
ejudge-change-contests --close --no-register 1-10
```

Сделать турнир 7 видимым и разрешить доступ к `users` со всех IP:

```bash
ejudge-change-contests --visible --all-users 7
```

Выдать пользователю `admin` полномочия `MASTER` на уровне турниров 3–5, а
также на глобальном уровне, с регистрацией в БД и обновлением имени:

```bash
ejudge-change-contests --add-master-cap admin --db --global --name "Admin Adminov" 3-5
```

Снять у пользователя `oldjudge` все полномочия (турнир 2), заблокировав его в
турнире в БД, без аудит-комментария:

```bash
ejudge-change-contests --no-audit --remove-cap oldjudge --db --lock 2
```

Удалить глобальные полномочии и oauth-алиас пользователя `former`:

```bash
ejudge-change-contests --global --oauth --remove-cap former
```

## Примечания

- Утилита изменяет только турниры, которые **уже существуют** на диске;
  создавать турниры она не умеет.
- Редактирование `contest.xml` выполняется «точечно»: сохраняется содержимое до
  открывающего тега `<contest ...>` и после закрывающего `</contest>`,
  переписывается только сам элемент турнира, поэтому посторонний текст вне
  элемента не теряется.
- Операции `--db` и `--global` требуют корректно настроенный `ejudge.xml`
  (путь к сокету сервера пользователей и к `capabilities.xml`) и админские права
  в сервере пользователей.
- Для массовых однотипных операций над набором турниров удобно использовать
  диапазоны `N1-N2`, чтобы не перечислять номера по одному.
